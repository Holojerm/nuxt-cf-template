# For Coding Agents

**[CLAUDE.md](./CLAUDE.md) is the canonical project-standards document.** Read it first before starting any work. It is deliberately small — the stack, the directory map, the coding and styling rules, the commands, and an index of everything else.

**Do not read all the docs.** Detail lives in [`.claude/docs/`](./.claude/docs/), one file per subsystem, and CLAUDE.md's index table tells you which one matches what you are about to touch. Loading them all defeats the point: the split exists so a session spends its context on your task rather than on subsystems you are not changing.

**[DESIGN.md](./DESIGN.md) is the source of truth for anything visual.** Color, typography, spacing, component behavior, and accessibility rules all live there. Never hand-edit generated files like `app/app.config.ts` or `app/assets/css/main.css` — they are compiled from DESIGN.md and your edits will be overwritten.

**[TEARDOWN.md](./TEARDOWN.md) is how you remove a subsystem.** This template ships billing, referrals, an MCP worker, and more. If a fork does not need one, follow the ordered removal there rather than deleting files and chasing the type errors — the removals are cross-cutting and the order matters.

**`bun run ci` is the merge gate: it must pass before a change can merge.** It runs lint, design-token validation, brand-asset validation, reference validation, SEO checks, typecheck, unit tests, browser suites for accessibility and for the Content-Security-Policy, and a production build. It is a gate on the finished work, not a precondition for starting — run it when you have something to merge, and again after any change you think is trivial. If anything in it fails, the code cannot merge. Fix the failure, do not work around it.

**[`.claude/docs/gotchas.md`](./.claude/docs/gotchas.md) documents the silent failure modes that have actually bitten this repo.** Read it before debugging. Three of them are load-bearing: the local D1 database lives in two places (only one is real), migrations are not applied on deploy (you have to run them manually), and `bun dev` caches its DB connection so external writes need a restart. Another three are Nuxt gotchas that fail quietly rather than loudly: custom `definePageMeta` keys silently produce an empty sitemap, `kv` is typed everywhere but not always injected at runtime (so a rate limiter fails open and only the logs know), and `nuxt-auth-utils` calls `/api/_auth/session` with an underscore — leave that prefix out of the auth middleware's allowlist and sign-out and session refresh 401 instead of producing nothing. If something appears to work but produces no output, or fails only for signed-in users, check that file first.

**Comments that name a symbol, file, or column are checked.** `bun run mirror:check` resolves every backticked reference in a comment against the codebase, so a rename that leaves a stale pointer behind fails the build rather than misleading the next agent. Keep the references accurate, or drop them.
